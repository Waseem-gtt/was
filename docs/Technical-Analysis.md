# التحليل التقني للملفات — 0.13

تعرض صفحة **التحليل التقني** أربع أدوات جديدة: `pcap` و`certificate` و`supply-chain` و`supply-chain-diff`. تختار ملفًا من أدلة المشروع أو ترفع ملفًا أو تنشئ عينة اصطناعية، ثم تشغّل التحليل وتحفظ النتيجة منفصلة عن الأصل. يمكن تنزيل التقرير بصيغة JSON وعرض النتائج المحفوظة بعد إعادة تحميل الصفحة. تحمل النتائج معرّفات الأصل والنتيجة وبصماتهما وإصدار المحرك؛ عرض نتيجة تاريخية لا يعيد تحليل الملف بإصدار أحدث.

تستخدم الأدوات واجهة `POST /api/run` الحالية، ويمكن إدراج معرّفاتها في خطط التحليل المحفوظة. تعمل داخل عامل Python محدود الذاكرة والمعالج والوقت، دون التقاط حي أو اتصال خارجي أو تشغيل الملفات المرفوعة. حد المدخل العام 4MiB؛ حد الشهادات أصغر. تظل بيانات التشغيل خارج Git وتشملها النسخ الاحتياطية المشفرة. الحدود ليست عزل ملفات أو شبكة عن هوية نظام التشغيل.

## تسجيلات الشبكة PCAP

تقبل `pcap` ملف classic PCAP ثنائيًا، أو كائن JSON مضبوطًا إلى حقل واحد:

```json
{"pcap_base64":"…"}
```

يدعم المحلل ترتيبَي البايتات ودقتَي الميكروثانية والنانوثانية، وEthernet مع حتى وسمَي VLAN، وRaw IP بنوع الربط101. يفحص رؤوس IPv4 وIPv6، وحتى8رؤوس امتداد IPv6، ويجمع بيانات وصفية لبروتوكولات TCP وUDP وICMP. تعرض النتيجة عدد الحزم والبايتات والبروتوكولات والتدفقات وعناوينها ومنافذها عند إمكان تفسيرها. لا تُستنتج منافذ من أجزاء حزم تحتاج إعادة تجميع.

الحدود:4MiB، و5000حزمة، و1000تدفق. ملف مبتور أو حزمة التقطت جزئيًا `caplen < origlen` أو تجاوز حد يرفض التحليل كله؛ لا تُقدّم نتيجة جزئية كأنها كاملة. لا يدعم PCAPNG أو إعادة تجميع التدفقات أو فحص صحة checksums أو فك TLS أو تحليل كل البروتوكولات. لا يصدر محتوى الحمولة، ولا يلتقط واجهة شبكة حية؛ تسجيل مشروع قد يتضمن بيانات حساسة، ولذلك يبقى أصلًا خاصًا بالمالك.

## شهادات X.509

تقبل `certificate` شهادة DER واحدة أو شهادات PEM، أو كائن JSON بحقل `certificates_pem` وحقل اختياري `validation_time` بطابع زمني ذي إزاحة صريحة. ترفض مفاتيح خاصة أو بيانات إضافية بعد الشهادة. الحد256KiB، وحتى10شهادات و100اسم بديل و50امتدادًا للشهادة.

تستخرج الموضوع والجهة المصدرة والرقم التسلسلي وفترة الصلاحية وبصمات الشهادة والمفتاح، ونوع المفتاح وحجمه وخوارزمية التوقيع، وSAN وBasic Constraints وKey Usage وEKU. تفصل بين تطابق اسمَي المصدر والموضوع وبين التحقق الفعلي من التوقيع الذاتي. تتحقق أيضًا من توقيع الروابط المباشرة بين الشهادات المقدمة متى كانت خوارزميتها مدعومة، وتظهر التوقيع غير الصحيح أو غير المدعوم بوضوح.

لا تستخدم ساعة ضمنية للحكم على الصلاحية: دون `validation_time` تبقى حالة الزمن `not_evaluated`؛ وعند تحديده يقارن بالتواريخ المسجلة فقط. صحة توقيع ذاتي أو وجود جذر ضمن الملف لا يمنح ثقة. تظل `trust:not_evaluated`؛ لا تحقق PKIX كاملًا أو مخزن ثقة أو اسم مضيف أو OCSP/CRL أو اتصال بموقع. التنبيهات عن مفاتيح أو خوارزميات ضعيفة ملاحظات فحص وليست شهادة سلامة.

## مكونات البرمجيات واعتمادياتها

تقبل `supply-chain` مجموعات موثقة من CycloneDX1.5/1.6 JSON وSPDX2.3 JSON. توحد معرف المكون واسمه وإصداره وتراخيصه وPackage URL والبصمات المعلنة، وتنتج رسم اعتماديات وملاحظات عن غياب الإصدار أو الترخيص أو البصمة، والدورات، وتعارض البصمات المعلنة للمكون نفسه.

الحدود:4MiB، و1000مكون، و5000رابط اعتماد، و1000تصريح ثغرة، وعمق JSONحتى32و100000عقدة. ترفض المراجع المجهولة والتكرار غير الصالح والاعتماد على الذات. دورات عدة مكونات تظهر كملاحظات؛ لا يُختلق ترتيب تثبيت لها. فيSPDXتفسر `DEPENDS_ON` و`DEPENDENCY_OF` فقط؛ لا تدعم الاعتماديات في مستند خارجي، وتبين أعداد العلاقات الأخرى المتجاهلة.

الثغرات والتقديرات الرقمية ودرجات الشدة الموجودة في المصدر تصريحات محفوظة، لا نتيجة بحث حي أو تحقق من التأثر الفعلي. غيابها لا يعني خلو المكونات من الثغرات. لا يثبت المحلل الملفات أو يقرأ محتواها للتحقق من بصماتها، ولا يثبت قانونية الترخيص أو صحة المصدر أو مصدرية البناء أو اكتمال معيارَي SBOM بكل امتداداتهما.

## مقارنة قائمتي مكونات

تقبل `supply-chain-diff` ملفJSONبحقلين فقط، كل منهما مستندSBOMمدعوم كامل:

```json
{"left":{"bomFormat":"CycloneDX","specVersion":"1.6","components":[]},"right":{"bomFormat":"CycloneDX","specVersion":"1.6","components":[]}}
```

تظهر المكونات المضافة والمحذوفة والحقول المتغيرة، والاعتماديات المضافة والمحذوفة، وتغير تصريحات الثغرات. تُقارن جميع عناصر الجرد المدعومة دون اقتطاع؛ تغير معرف مكون يعامل كإضافة وحذف. `normalized_inventory_equal` حكم على الحقول الموحدة الموثقة فقط، وليس مساواة جميع حقول المصدر أو بايتاته أو ضمان توافق ترقية البرنامج.

تحدد `left_sha256/right_sha256` ترميزJSONالقياسي للمستندين المضمنين، كما يوضح `embedded_document_encoding:canonical_json`. تحدد `source_bundle_sha256` بايتات ملف المقارنة المرفوع كاملًا، وتبقى بصمة دليل الأصل ضمن نتيجة سير العمل. حدود المدخل4MiBللحزمة، وتطبق حدود الجرد على كلا الطرفين.

هذه الأدوات توسع قدرات الملف الأصلي ضمن نطاقات محددة، ولا تكمل كل تقنيات العالم أو التكاملات الإنتاجية. راجع[محولات Windows XML](Event-Adapters.md)، و[حالة التنفيذ](Implementation-Status.md)، و[واجهات API](API.md)، و[تقرير تحقق0.13](Validation-0.13.md).
