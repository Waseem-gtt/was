# محولات الأحداث المحلية — 0.13.0

أربعة محولات حتمية تقرأ ملفات مرفوعة داخل عامل التحليل المحدود بالوقت والذاكرة. لا تفتح شبكة، ولا تستقبل Syslog حيًا، ولا تشغّل أوامر أو ملفات مرفوعة. النتيجة صيغة داخلية `was.event/1`؛ دعم OCSF الكامل ما زال غير منفذ. هذه خطوة لتوحيد البيانات وليست حكمًا على وقوع هجوم أو فعالية الحماية.

## الاستخدام والحدود

تستقبل أداة `events` الشكل الجديد التالي، مع رفض المفاتيح الإضافية أو الناقصة:

```json
{"adapter":"windows-json","content":"[{\"time\":\"2026-01-01T00:00:00Z\",\"event_id\":4625}]"}
```

قائمة أحداث JSON القديمة في أداة `events` تحتفظ بسلوكها السابق. الحدود التالية خاصة بالمحولات الجديدة:

- المحتوى UTF-8 من بايت واحد إلى 1MiB، ومن سجل واحد إلى 1000 سجل؛ لا إسقاط ولا اقتطاع للسجلات غير الصالحة. الخطأ في أي سجل يرفض الدفعة كلها. قد يذكر المحول رقم السجل؛ أخطاء بنية JSON أو XML أو رأس CSV أو الحدود العامة تخص الدفعة.
- سجل واحد حتى 8192 بايت: النص الخام في Syslog، وتمثيل JSON غير المهرب لـUnicode في Windows وCSV. أسطر Syslog وCSV حتى 8192 بايت أيضًا. لا يطبق حد السطر على مصفوفة Windows JSON المدمجة؛ يطبق حد كل سجل. فيWindows XMLيُفحص حجم عنصرEventالخام أيضًا قبل الاحتفاظ به.
- الزمن `unknown` أو RFC3339 مع تاريخ صحيح وثوانٍ وإزاحة صريحة `Z` أو `±HH:MM` وجزء ثوانٍ اختياري من 1 إلى 7 خانات. لا إضافة لمنطقة زمنية إلى تاريخ محلي. تبقى السلسلة الأصلية كما هي، بما فيها `-00:00` التي تعني إزاحة محلية غير معلومة؛ لا تحويل إلى UTC. الثواني الكبيسة غير مدعومة.
- المخرجات تتضمن `schema, adapter, events, count, failed, limitations, input_sha256`. البصمة للمحتوى UTF-8 كما قُدم، بما فيه نهايات الأسطر. `failed` يعد فقط قيمة `outcome` الصريحة `failure`.
- لكل حدث `time,actor,action,outcome,original`. الحقول غير المعلومة تظل `unknown`. يبقى `original` كائن JSON الأصلي أو حقول صف CSV النصية، أو سطر Syslog دون فاصل السطر؛ ليس إعادة بناء للملف الأصلي. ملف الدليل الأصلي وبصمته محفوظان بشكل منفصل.
- JSON يرفض تكرار المفاتيح والقيم العددية غير المنتهية. جميع التحويلات محلية؛ لا رفع للمحتوى إلى خدمة خارجية.

## Windows JSON

مصفوفة من كائنات بأحد الشكلين التاليين لكل سجل. ليست هذه جميع صيغ تصدير Event Viewer؛ يجب إعداد التصدير وفق الشكل الموثق. لا يقبل XML ولا تفاصيل `#text` ولا `@Name`.

الشكل المسطح:

```json
[{"time":"2026-01-01T00:00:00Z","event_id":4625,"actor":"demo","action":"login","outcome":"failure","host":"pc"}]
```

`time,event_id` مطلوبان. بقية الحقول المعروضة اختيارية؛ المفاتيح الأخرى مرفوضة. `event_id` عدد صحيح من 0 إلى 65535، وليس قيمة منطقية. `outcome` إحدى `unknown,success,failure` فقط. بقية القيم سلاسل غير فارغة.

الشكل الهرمي المدعوم:

```json
[{"System":{"EventID":4625,"TimeCreated":{"SystemTime":"2026-01-01T00:00:00Z"},"Computer":"pc","Channel":"Security","Provider":"demo"},"EventData":{"TargetUserName":"demo","Extra":"preserved"}}]
```

`System.EventID` و`System.TimeCreated.SystemTime` مطلوبان. `Computer,Channel,Provider` سلاسل اختيارية. `EventData` اختياري وقيمه سلاسل فقط؛ `TargetUserName` هو مصدر `actor` إن وجد. يحفظ الكائن كله في `original`، دون تحويل تلقائي لأرقام الأحداث إلى نجاح أو فشل أو أسماء هجمات. لا تدعم هذه النسخة كائن Provider المتداخل أو مصفوفة EventData.

## Windows XML — 0.13

معرف المحول `windows-xml`. يقبل عنصر `Event` واحدًا، أو غلاف `Events` يضم عناصر أحداث. يلزم فضاء أسماء Windows للأحداث والعناصر الداخلية `http://schemas.microsoft.com/win/2004/08/events/event`؛ يمكن أن يكون الغلاف وحده دون فضاء أسماء. مثال اصطناعي:

```xml
<Events>
  <Event xmlns="http://schemas.microsoft.com/win/2004/08/events/event">
    <System>
      <Provider Name="SyntheticProvider"/>
      <EventID>4625</EventID>
      <TimeCreated SystemTime="2026-10-20T00:00:00.1234567Z"/>
      <Computer>synthetic-host</Computer>
      <Security UserID="S-1-0-0"/>
    </System>
    <EventData><Data Name="TargetUserName">synthetic-user</Data></EventData>
  </Event>
</Events>
```

`System.EventID` و`TimeCreated.SystemTime` مطلوبان. يدعم مجموعة مضبوطة من حقول `Provider,Computer,Channel,EventRecordID,Version,Level,Task,Opcode,Keywords,Security,Execution,Correlation` وخصائصها الموثقة في المحلل. يقبل `EventData` حقول `Data` النصية ذات `Name` فريد فقط؛ لاUserDataأوRenderingInfoأو أشجارXMLاعتباطية. يأخذ `actor` من `TargetUserName`، ثم من `Security.UserID` عند غياب الأول. تبقى `action/outcome` غير معلومتين؛ رقم4625لا يتحول تلقائيًا إلى حكم فشل أو هجوم.

يحفظ `original` البنية الموحدة لـSystemوEventData؛ لا يعيد إنتاج تنسيقXMLالأصلي. يبقى الملف المرفوع وبصمته الأصلية منفصلين. تُحفظ الطوابع الزمنية ذات7خانات كما وردت لتجنب فقد دقة100نانوثانية؛ لا تعني موافقة الصيغة إثبات دقة ساعة الجهاز.

الحدود العامة1MiBو1000حدث و8192بايت للحدث، وعمقXMLحتى8و128000عنصر إجمالًا، وحتى128ابنًا للعقدة. يرفض المحللDTDوتعريفات الكيانات والتعليمات المعالجةPIوالكيانات الخارجية وXIncludeوفضاءات الأسماء الأجنبية والتكرار والبنية غير المدعومة. يسمح بإعلانXML1.0اختياري معUTF-8فقط. يُفحص الحد أثناء التحليل، وأي خطأ يرفض الدفعة كلها؛ لا قراءة ملفات أو جلب روابط خارجية. هذا محول لتصديرXMLالموثق وليس قارئEVTXأو جامعWindowsحيًا.

## Syslog RFC5424

سجل إصدار 1 لكل سطر، مع LF أو CRLF ونهاية سطر أخيرة اختيارية. الأسطر الفارغة غير مقبولة. الأولوية بين 0 و191 دون أصفار بادئة؛ يشتق `facility` و`severity` رقميًا دون تفسيرهما كحكم أمني.

```text
<34>1 2026-01-01T00:00:00Z host app 123 ID47 [example@32473 key="value"] example message
```

الطابع الزمني `-` يتحول إلى `unknown`. حقول الرأس ASCII قابلة للطباعة وفق أطوال RFC5424: المضيف 255 والتطبيق 48 ومعرف العملية 128 ومعرف الرسالة 32. يدعم الجزء المنظم NILVALUE `-` أو عناصر متجاورة `[id key="value"][other]`، مع فحص أسماء المعرفات والمعلمات وهروب `\"` و`\\` و`\]` ورفض التكرار والهروب غير الصالح. يحفظ الجزء المنظم الخام في `structured_data` والرسالة في `message`. لا يدعم استمرار سجل على أسطر متعددة، أو تجزئة octet-counting، أو RFC3164. لا يستنتج `actor,action,outcome` من نص الرسالة.

## تدفقات CSV

الرأس المطلوب حرفيًا `time,source,destination,protocol,bytes`، بأي ترتيب. يمكن إضافة `action,outcome` فقط؛ تكرار الرأس أو الأعمدة الزائدة أو الناقصة مرفوض. يدعم CSV الاقتباس، بما فيه الفواصل داخل الحقول، دون تساهل في الاقتباس غير المكتمل.

```csv
time,source,destination,protocol,bytes
2026-01-01T00:00:00Z,192.0.2.1,198.51.100.2,TCP,128
```

المصدر والوجهة عناوين IPv4 أو IPv6، وليسا أسماء مضيفين. البروتوكول من 1 إلى 32 محرف ASCII: يبدأ بحرف أو رقم ثم حروف أو أرقام أو `._-`. `bytes` عدد صحيح عشري من 0 إلى `2^64-1` دون إشارة أو أصفار بادئة. لا تستنتج نتيجة الاتصال أو اتجاهه أو منافذه. يحتفظ `original` بسلاسل الصف قبل تحويل عنوان IP أو عدد البايتات.
