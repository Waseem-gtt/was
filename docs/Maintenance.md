# الصيانة والتطوير وترقية لينكس — 0.5

القائمة العلوية «إدارة البرنامج» متاحة من صفحات التطبيق. صفحة «التحديث والصيانة» تفحص جميع الأقسام أو قسمًا معينًا، ولكل قسم مدخل مباشر يختاره مسبقًا. تحديث المعرفة يفتح مصدر CISA الموجود؛ لا يعني تنزيل أو ترقية أدوات التخصص.

## الفحص والإصلاح

الفحص يستدعي SQLite quick_check والمفاتيح المرجعية ويتحقق من سلسلة التدقيق المحلية. يتحقق من SHA-256 وحجم ونوع الأدلة، بحد500ملف و64MiB وثلاث ثوانٍ لمرحلة قراءة الأدلة؛ لا يعلن النجاح عندما يتبقى أي دليل. نتيجة البيانات عامة لجميع المشاريع حتى عند اختيار قسم. تُشغّل الأدوات المرتبطة بالقسم على عينات ثابتة عبر العامل المحدود؛ اختبار IOC والبصمات يتحقق من قيم مرجعية، وباقي العينات تتحقق من نجاح التشغيل وبنية النتيجة. هذا ليس تقييم فعالية دفاعية لكل تخصص أو فحص ثغرات نظام التشغيل.

«إصلاح الصلاحيات وإعادة الفحص» يعيد المجلدين المعروفين إلى0700 وقاعدة البيانات المتحققة إلى0600 وملفات الأدلة التي اجتازت التحقق إلى0400. يستخدم واصف ملف دون اتباع روابط رمزية. لا يحذف أدلة، ولا يعيد بناء محتوى تالف، ولا يعيد كتابة سجل تدقيق منكسر. الفشل أو عدم اكتمال الفحص يظهر بوضوح. تُحفظ آخر50عملية ويعرض أحدث10؛ النسخ الاحتياطية المشفرة تشمل السجل وطلبات التطوير.

في0.6تُثبت واصفات المجلدات والملفات طوال عملية الإصلاح، وتُقارن هويتها بهوية التخزين منذ فتحStore. تُفحص البصمة على واصف الملف نفسه الذي ستتغير صلاحياته، وتُرفض الروابط الصلبة والرمزية والملفات المستبدلة. قبل التطبيق وبعده تُعاد فحوص الهوية والمحتوى والصلاحيات. عند فشل خطوة تُحاول إعادة الصلاحيات السابقة عبر الواصفات المثبتة، وتظهر حالات `rolled_back` أو `rollback_failed` صراحة. لا يعني الرجوع للصلاحيات إعادة محتوى تالف. فشل اختبار أداة لاحقًا لا يعكس معاملة صلاحيات ناجحة ولا يدعي أنه أصلح الأداة.

حد64MiBهو مجموع قراءات التحقق، بما فيها إعادة القراءة قبل الإصلاح وبعده؛ قد يصل الفحص إلى الحد قبل قراءة64MiBمن الملفات المختلفة. أي توقف للحدود يظهر كفحص غير مكتمل. عندما تكون هوية التخزين غير متحققة، يُرد التقرير للواجهة مع `persistence: blocked` دون الكتابة إلى مسار تخزين بديل. عند تعذر حفظ SQLiteتظهر `persistence: failed` ولا يعلن التقرير الاجتياز. وجود مدير جهاز مخترق خارج حد الثقة المحلي؛ هذه الضوابط لا تمثل حماية كاملة منه.

طلبات التطوير مرتبطة بقسم؛ حالاتها مفتوح، قيد التطوير، ومنجز حسب مراجعة المالك. الحد1000طلب. تغيير الحالة قرار متابعة، وليس تنفيذ كود أو شهادة قبول. جميع المسارات محمية بتسجيل الدخول، والعمليات المعدلة محمية بـCSRF. الفحص الثقيل يتشارك قفل التنفيذ مع التحليل والجدولة.

## ترقية البرنامج

هذه أداة إدارة محلية، ولا يوجد مسار HTTP ينفذ Git أو pip أو أوامر النظام. يلزم Git وPython3.11+ وNode وChromium وflock وtar وsha256sum. يلزم اتصال PyPI ومراجعة مصدر Git الخاص. لا تشغّلها على التزام غير موثوق: كود الاختبارات والبناء يُنفذ أثناء التجهيز. SHA يحدد المصدر ويكشف تغيره؛ **ليس توقيع ناشر أو ضمانًا لخلوه من البرمجيات الضارة**.

من المستودع الخاص، اجلب main بالطريقة المعتادة، ثم اختر SHA كاملًا راجعته. لا تغير الأداة عنوان المستودع أو خصوصيته، ولا تنسخ بيانات التشغيل. اختر مجلد إصدارات جديدًا خاصًا بصلاحية0700 خارج مجلد الأدلة:

```bash
git fetch origin main:refs/remotes/origin/main
# استبدل REVIEWED_COMMIT_SHA بقيمة كاملة من40محرفًا بعد مراجعتها
bash scripts/release.sh prepare REVIEWED_COMMIT_SHA /absolute/private/was-releases
```

يجب أن يكون الالتزام في تاريخ origin/main المحلي. يُنشأ إصدار مستقل، مع venv دائم في مساره النهائي، واعتماديات إنتاج مثبتة ببصمات، وفحص الملف الأصلي، واختبارات الوحدة، وصياغة JavaScript، وBandit وpip-audit والمتصفح وبناءwheel. فشل أي خطوة يترك الإصدار غير جاهز ولا يغير current. لا يُعاد استخدام مجلد تجهيز سابق تلقائيًا؛ افحصه عند الفشل، وأزله يدويًا إذا كان مجرد نسخة تجهيز خاصة بك. فحص الاعتمادات يعتمد على توفر قاعدة PyPI وقت التجهيز؛ الانقطاع يمنع الجاهزية.

بعد النجاح: صدّر نسخة بيانات مشفرة واحفظ كلمة حمايتها محليًا، أوقف الخدمة القائمة من مدير الخدمة أو Ctrl+C، ثم فعّل الإصدار:

```bash
bash scripts/release.sh activate REVIEWED_COMMIT_SHA /absolute/private/was-releases
bash /absolute/private/was-releases/current/scripts/start.sh --data /absolute/private/was-data
```

التفعيل يعيد فحص بصمات ملفات المصدر التي قُرئت من Git، ثم يبدل current ذريًا ويحفظ previous. لا يعيد تشغيل الخدمة أو يحذف البيئة القديمة. عند الحاجة، أوقف الخدمة أولًا ثم:

```bash
bash scripts/release.sh rollback /absolute/private/was-releases
```

الرجوع يبدل إصدار **الكود** فقط. لا يعكس ترحيل قاعدة بيانات. في0.5أضيف جدولان دون تعديل السجلات القديمة؛ لأي إصدار لاحق اقرأ توافق البيانات واختبر الاستعادة إلى مجلد جديد قبل تشغيل إصدار قديم. ملفات الجاهزية والبصمات المحلية ليست محمية من مدير الجهاز. مسار تثبيت بإصدارات موقعة وTUF وتحديث كل حزم لينكس لم يُنفذ.

## تشغيل كبرنامج لينكس

بعد التثبيت شغّل `bash scripts/desktop.sh --data /absolute/private/was-data`. يبدأ التطبيق الخاص علىloopback ويفتح واجهته في متصفح سطح المكتب الافتراضي؛ إبقاء الطرفية مفتوحة ضروري، وCtrl+C يوقفه. لا توجد نافذة Electron أو توزيعة نظام تشغيل جديدة.

لإضافة أيقونة لقائمة تطبيقات سطح المكتب، انسخ deploy/was-platform.desktop إلى مجلد تطبيقات المستخدم وعدّل Exec إلى المسار المطلق لمشغل desktop.sh. إذا احتوى المسار مسافات فاستخدم اقتباس Desktop Entry المناسب. لا يتطلبroot. بعد ترقية مُدارة اجعل Exec يشير إلى current/scripts/desktop.sh. اختُبر مشغّلCLI والمحاكاة، ولم تُختبر جلسة سطح مكتب رسومية فعلية في هذه البيئة.
