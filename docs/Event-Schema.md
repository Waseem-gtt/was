# F03 — لغة مشتركة للأحداث الأمنية: وظائف منفذة ومختبرة

تحديث0.20: الوظائف المذكورة منفذة ومختبرة، لكن الدفعة والقسم المرتبط غير مكتملين وفق [توجيه المالك النافذ](Completion-Policy-0.20.md). المرجع الحالي [كشف التسليم](Delivery-Status-0.20.md).

يحدد البند F03 في المصدر محولات وقاموسًا ونسخ مخطط وحفظ الأصل والتوقيت والجودة. يوفر التنفيذ هذه العناصر لصيغ Windows JSON وWindows XML وSyslog RFC5424 وتدفقات CSV الموثقة. OCSF مرجع تصميم مرشح في المصدر؛ لا يمثل هذا التنفيذ توافقًا كاملًا معه أو قارئ EVTX أو مستشعرًا حيًا، ولا تُفرض صيغة أحداث أمنية على عينات الفيزياء والرادار.

## القاموس والمخطط والإصدار

يعرض GET /api/events/schema القاموس was.event/1 بإصدار 1.0.0 وبصمة SHA-256 لمحتواه. يشمل تعريف الحقول وأنواعها ومعانيها والحقول المطلوبة والمسموح بها لكل محول، وقائمة رموز جودة البيانات، ومخططات JSON Schema محلية لكل نوع سجل. لا تُجلب عناوين تعريف JSON Schema من الإنترنت. يتحقق منفذ Python من الأنواع والحقول والعلاقات الدلالية؛ الوصف ليس بطاقة واجهة فقط.

تحتفظ النتيجة باسم المخطط والإصدار وبصمة القاموس، ويتحقق القارئ من نسخة مدعومة عند إعادة القراءة. الإصدار المجهول أو البصمة المختلفة مرفوضان. أي تغيير في تنفيذ القاموس يغيّر بصمة محرك التحويل؛ لا تنسب نتيجة قديمة إلى القارئ الجديد دون إعادة تحقق.

## الأصل والتحويل

يبقى ملف الإدخال ببايتاته وبصمته SHA-256 دليلًا أصليًا منفصلًا. ترتبط النتيجة الموحدة به بواسطة معرف الأصل والبصمة وعلاقة أصل–مشتق. حقل original يحفظ تمثيل السجل المدعوم قبل التطبيع: كائن السجل في JSON/CSV/XML، أو السطر في syslog. ليس الحقل بديلًا عن بايتات ملف XML الأصلية؛ حفظ الملف الكامل مسؤولية خدمة الاستيراد التي تختبر المصدر قبل تشغيل العامل وبعده.

يعمل التحويل في عامل Python موثوق محدود الموارد، وليس تشغيلًا لشيفرة السجل. يرفض أي سجل غير صالح الدفعة كاملة قبل حفظ مشتق، ولا يُخفى فشل سجل أو يحذف تكرارًا. الترتيب وعدد التكرارات يبقيان كما في المصدر. الحد 1 ميبيبايت و1000 سجل و8192 بايت للسجل وفق المحول. تبقى محولات التطبيق محددة وثابتة؛ لا يختار محتوى الملف محولًا برمجيًا أو أمرًا.

## التوقيت والجودة

تُحفظ سلسلة التوقيت الأصلية وإزاحتها دون تحويل يفقد الدقة، بما في ذلك كسور Windows ذات 7 منازل. unknown يعني غياب التوقيت. الإزاحة -00:00 تبقى كما وردت وتظهر offset_known:false؛ لا يعاد تفسيرها كتوقيت UTC مؤكد. تقرير التوقيت يحفظ رقم السجل والنص والإزاحة وعدد المنازل الكسرية، ولا يدعي قياس دقة الساعة نفسها.

يتضمن quality عدد السجلات وعدد السجلات ذات الفجوات وعدد حقول time/actor/action/outcome المجهولة، وقائمة فجوات كل سجل. الرموز هي unknown_time وunknown_actor وunknown_action وunknown_outcome وoffset_unspecified. غياب الفعل أو نتيجة العملية لا يتحول إلى استنتاج هجوم أو نجاح؛ ولا يحول رقم EventID ضمنيًا إلى نتيجة مصادقة. تُشتق الجودة من كامل السجلات المتحققة، وتُراجع عند إعادة التشغيل؛ تقرير جودة مزور أو تعداد خاطئ مرفوض.

## معيار القبول

- قاموس ومخطط وإصدار وبصمة قابلة للفحص والتنزيل من الواجهة.
- نجاح جميع المحولات الأربعة في إنتاج نتيجة موحدة متحققة، مع الأصل والتوقيت والجودة.
- رفض الأنواع والحقول غير المدعومة والتعدادات غير المتسقة، دون حفظ نتيجة ناقصة.
- حفظ الترتيب والتكرار والإزاحات والدقة الكسرية، مع إظهار الفجوات بدل اختراع قيم.
- ربط النتيجة بالأصل وإعادة التشغيل في عامل محدود للتحقق من تطابقها، ورفض تغير القارئ أو المصدر أو الجودة.

التعامل القديم مع مصفوفة الأحداث التعليمية المباشرة يبقى متوافقًا؛ القاموس الجديد يخص المحولات الأربعة المسجلة في خدمة الاستيراد. راجع tests/test_event_schema.py واختبارات المحولات وWindows XML لاختبارات القبول.
