# F06 — خريطة العلاقات والأدلة المشتركة

تحديث0.20: الوظائف المذكورة منفذة ومختبرة، لكن الدفعة والقسم المرتبط غير مكتملين وفق [توجيه المالك النافذ](Completion-Policy-0.20.md). المرجع الحالي [كشف التسليم](Delivery-Status-0.20.md).

الشروط الأصلية في [ملف المتطلبات](Requirements-Source.md)، السطر68وفقرة القسم01: أصل وبرنامج وثغرة وحدث ودليل وتجربة، مع مصدر وثقة وصلاحية وتعارض ووقت الملاحظة، والتفويض قبل العرض والبحث والاسترجاع للذكاء الاصطناعي.

## الاستخدام

اختر مشروعًا، وأضف ملف المصدر من صفحة الأدلة، ثم افتح «خريطة الأدلة». تعرض لوحة «خريطة الكيانات والمصادر والثقة» الكيانات والعلاقات وتفاصيلها وجداول مكافئة. أضف كيانًا وحدد نوعه واسمه ووصفه ومصدره والثقة ووقت الملاحظة. النوعان «دليل» و«تجربة» يحتاجان أيضًا ملفًا فعليًا من المشروع مرجعًا لهما؛ يمكن ربط نتيجة تحليل محفوظة. تظل نتيجة التجربة مرتبطة بما حفظه المالك؛ إنشاء عقدة لا يشغّل تجربة ولا يثبت صحة محتواها.

أضف علاقة بين كيانين وبيّن معناها ومصدرها وثقتها ووقت ملاحظتها. أنواعها: ارتباط، تشغيل، تأثير، ملاحظة على، اشتقاق، دعم، تعارض، واختبار بواسطة. يمكن تسجيل تعارض صريح مع علاقة سابقة، ويظهر أيضًا وجود ادعاء داعم وآخر معارض للكيانين نفسيهما. يحتفظ النظام بالادعاءين ومصدريهما دون اختيار أحدهما بوصفه حقيقة.

وقت الملاحظة مطلوب بصيغةRFC3339مع إزاحة معلومة. بداية الصلاحية ونهايتها اختياريتان، وتُرفض فترة معكوسة. يوضح العرض حالة الصلاحية عند الوقت الحالي أو وقت يحدده المالك؛ لا يحذف الادعاء المنتهي. الثقة من0إلى100هي تقدير المالك الموثق، وليست درجة صحة يولدهاAI. الضغط على العقدة أو العلاقة يعرض شرحها ومصدرها وتوقيتها وبصماتها. البحث يعمل في بيانات الخريطة الخاصة بالمشروع بعد تحقق الخادم منها، والتنزيل يصدر وصف الخريطة دون بايتات ملفات المصدر.

## التخزين والتحقق

لكل كيان وعلاقة معرف ثابت وسجلJSONغير مستبدل في مخزن الأدلة الخاص. يحتفظ السجل ببصمة المصدر وبصمة مرجع الدليل أو التجربة. تتطلب القراءة تطابق كامل عضوية السجلات مع أحداث إنشائها في التدقيق، وفحص بايتات السجلات والمصادر والمراجع. حذف سجل أو إضافة نسخة مرفوعة لا يمنحها صفة سجل معتمد. يُرفض مصدر من مشروع آخر، أو مصدر ادعاء غير أصلي، أو علاقة ذات طرف مفقود، أو مرجع تعارض غير محفوظ.

الحفظ يجمع ملف السجل وبياناته وعلاقة الأصل والتدقيق في معاملة متراجعة عند الفشل، مع تثبيت مجلد الأدلة وفحصه. تُحجز معاملةSQLiteقبل التحقق والإضافة لتسلسل عمليات الكتابة بين اتصالاتStoreالمختلفة. لا يعطي ذلك ضمانًا أمام مدير جهاز يتحكم في الشيفرة والتخزين.

الحدود:128كيانًا و256علاقة لكل مشروع؛1ميبيبايت لكل مصدر أصلي و4ميبيبايت لكل ملف مرجع و8ميبيبايت لمجموع بايتات المصادر والمراجع المختلفة التي تُراجع؛16كيبيبايت للسجل و2ميبيبايت لمجموع السجلات. يرفض تجاوز الميزانية القراءة أو الحفظ بدل تصدير خريطة ناقصة بوصفها كاملة. الرسم يعرض30عقدة في المرة مع البحث والجداول الكاملة لجميع السجلات المتحققة.

## الواجهات والصلاحيات

- GET /api/graph?project=ID: السجلات المتحققة والتعارضات وقاموس الأنواع والحدود. atاختياري لتقييم الصلاحية بتوقيتRFC3339.
- POST /api/graph/entities: الحقلانproject_idوentityفقط.
- POST /api/graph/relations: الحقلانproject_idوrelationفقط.

جميع الواجهات تتطلب جلسة المالك قبل قراءة بيانات المشروع، والحفظ يتطلبCSRFوالأصل الصحيح. تُرفض الحقول الزائدة. قفل المهام الثقيلة يغطي التحقق والحفظ ويُطلق قبل إرسال الاستجابة. ليست هناك مشاركة بين مستخدمين أو وصولAIمفوض تلقائيًا؛ الخريطة لا ترسل شيئًا إلى النموذج أو الشبكة. المساعد المحلي المنفصل لا يسترجع محتوى الخريطة تلقائيًا. تفويض المالك هو الحاجز المنفذ خارج النموذج.

تدخل ملفات الخريطة والتدقيق في النسخ الاحتياطية المشفرة والاستعادة القائمة. لا ترفع بيانات المشروع إلىGit؛ اختبارات التحقق تستخدم ملفات اصطناعية وأسرارًا مؤقتة. تظل روابط الأدلة القديمة ونتائج الإصدارات السابقة محفوظة.
