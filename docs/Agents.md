# فريق الوكلاء المحلي — 0.6

صفحة «فريق الوكلاء» توزع سؤال المالك ومقتطفات أدلة اختارها على أدوار تخصصية. السجل يحتوي40دورًا مختلفًا، تشمل المتطلبات والمعمارية والخادم والواجهة والاختبارات والحماية والخصوصية والتشفير والشبكات والتوثيق. افتراضيًا يعمل الباحث ومراجع الحماية ومراجع الجودة؛ يمكن اختيار مجموعة أو جميع الأدوار.

هذه40تعليمات تخصصية إلى **المحرك المحلي نفسه**، وليست40نموذجًا مثبتًا أو اشتراكًا مدفوعًا أو40عملية تعمل معًا. لا تحتوي الحزمة أوزان نموذج أو محرك استدلال. يتطلب التشغيل محركًا محليًا متوافقًا مع OpenAI chat completions مثل llama.cpp/Ollama، بالإعدادات المحلية الموجودة WAS_AI_URL وWAS_AI_MODEL. لا تُخزن مفاتيحAPIفيGitولا يرسل التطبيق محتوى المشاريع إلى مزود خارجي.

## توزيع العمل

اختر المشروع ثم المهمة وحتى أربعة أدلة. عند البدء تُحفظ مهمة وسجل لكل دور، وتبدأ المعالجة في الخلفية؛ يمكن متابعة الانتظار والجاري والنجاح والفشل من الواجهة. يستخدم المنسق طلبين متزامنين كحد أقصى، ومهلة20ثانية للطلب، ويشارك قفل المهام الثقيلة مع التحليل والصيانة. اختيار40دورًا قد يستغرق عدة دقائق، ولا يضمن أن المحرك أو ذاكرة الجهاز يدعمان الأداء المطلوب. تُحفظ النتيجة حتى عند فشل بعض الأدوار؛ الفشل الكلي لا يتحول إلى نجاح اصطناعي.

لكل طلب حد سؤال4000حرف، ولكل دليل مقتطف6000بايت فقط، وإجمالي4أدلة، ويُتحقق من انتمائها للمشروع وبصماتها. تنسيق الإجابة نص للمراجعة البشرية. تُحفظ حالة كل دور وتقرير مشتق كبند أدلة مع مصدر المهمة والأدلة المستخدمة. نتائج النموذج قد تحتوي أخطاء أو استشهادات غير صحيحة؛ وجود بصمة المصدر لا يثبت صحة استنتاجه.

لا يملك الوكلاء منفذ أوامر أو صلاحية تثبيت أو إصلاح أو تغيير ملفات أو نشر. التعليمات في الأدلة تُعامل بيانات غير موثوقة. إجراءات صيانة الملفات المنفذة تبقى في المسار المحدد والمختبر، ولا تنفذ نصًا يقترحه النموذج. هذه حدود تقنية في التصميم، وليست ادعاء اعتماد أو مطابقة كاملة لمعيار دولي.

## واجهات محمية

- `GET /api/agents/roles`: سجل الأدوار وحد التوازي وحالة متطلب المحرك.
- `POST /api/agents/start`: `project_id,question,evidence_ids,role_ids`؛ قائمة الأدوار اختيارية، ولا يقبل الطلب أوامر أو عنوان محرك جديدًا.
- `GET /api/agents?project=ID`: تاريخ مهام الوكلاء في المشروع.
- `GET /api/agents?project=ID&job=ID`: تفاصيل التقدم والنتائج؛ لا تُعرض مهمة مشروع آخر.

جميعها تتطلب تسجيل الدخول، وبدء المهمة يتطلبCSRF. عند إغلاق التطبيق تتوقف المهام المنتظرة ويُنتظر انتهاء الطلبات المحدودة الجارية قبل إغلاق قاعدة البيانات. إعادة التشغيل تحول المهام التي توقفت إلىinterrupted؛ لا يوجد استكمال آلي أو ادعاء نجاحها.

الاختبارات تستخدم محركHTTPمحليًا اصطناعيًا للتحقق من توزيع المهام والتزامن والحفظ والفشل والواجهة. هذا **ليس اختبار استدلال بنموذج حقيقي**. وكلاء المساعدة المستخدمون أثناء تطوير المستودع خدمة منفصلة عن هذا المنسق داخل المنتج.
