# التحقق من الإصدارات الموقعة

تضيف النسخة0.8 تحققًا محليًا من بيانات الإصدار بواسطة Ed25519 قبل إعداد إصدار Git محدد وتفعيله. لا تحمّل الأداة تحديثات، ولا تمنح واجهة الويب أو النموذج اللغوي صلاحية تثبيت البرامج. مشغّل لينكس الإداري وحده ينفذ خطوات الترقية بطلب المالك.

هذه صيغة محلية محدودة، وليست تطبيقًا لبروتوكول TUF أو شهادة أمن عالمية. يلزم مفتاح ثقة يثبّته المالك مسبقًا، وساعة نظام صحيحة، وحماية ملفات الثقة والحالة خارج إصدار التطبيق. لم يُنشأ مفتاح نشر حقيقي للمالك ولم تُثبّت له ثقة تلقائيًا. مفاتيح اختبارات المستودع مؤقتة ولا تصلح للنشر.

## إنشاء مفتاح المالك خارج المستودع

شغّل من نسخة البرنامج المراجعة مع بيئتها الافتراضية. استبدل المسارات بما يناسب حساب لينكس؛ يجب أن توجد المجلدات الأب، ويُرفض أي مكوّن مسار رمزي. لا تستخدم مجلد المشروع أو مجلدًا مشتركًا لحفظ المفتاح الخاص.

```bash
install -d -m 700 "$HOME/was-signing"
.venv/bin/python -m cyber_platform.release_admin keygen \
  "$HOME/was-signing/publisher.pem" \
  "$HOME/was-signing/trust.json"
```

تطلب الأداة كلمة مرور تفاعليًا بطول12 إلى256 حرفًا، وتحفظ المفتاح الخاص مشفرًا بصيغة PKCS8، بصلاحية0600. لا تمرر كلمة المرور في سطر الأوامر أو متغير بيئة أو المحادثة. احفظ نسخة احتياطية آمنة للمفتاح وكلمة مروره؛ فقدانهما يوقف إصدار توقيعات جديدة بهذا المفتاح. لا ترفع المفتاح أو كلمة مروره إلى GitHub، حتى إن كان المستودع خاصًا.

ملف `trust.json` عام من ناحية المحتوى؛ قيمته الأمنية في مصدره وصلاحياته. ثبّته عبر قناة موثوقة للمالك، وتحقق من معرّف المفتاح `keyid` الذي تعرضه عملية الإنشاء. المعرّف هو SHA-256 لبايتات مفتاح Ed25519 العام، ويجب أن يطابق محتوى الملف. تحميل مفتاح بجوار ملف الإصدار من المصدر نفسه لا يجعله موثوقًا تلقائيًا. لا يُسمح بملف ثقة قابل للكتابة للمجموعة أو الآخرين، ويجب أن يملكه المستخدم الحالي أو root.

## إعداد بيانات الإصدار والتوقيع

بعد تثبيت التغييرات ومراجعتها وبناء الحزم، أنشئ ملف بيانات JSON مستقلًا. المثال الآتي مولّد ببايثون لتفادي أخطاء الأطوال والتوقيت والحسابات؛ غيّر رقم التسلسل والإصدار ومعرّف Git ومسار الحزمة قبل تشغيله. معرّف Git أدناه عنصر نائب من40 رقمًا صفريًا، وليس إصدارًا قابلًا للتثبيت.

```bash
.venv/bin/python - <<'PY'
import hashlib
import json
import pathlib
import time

commit = '0000000000000000000000000000000000000000'  # استبدله بمعرّف Git الكامل المراجع
artifact = pathlib.Path('/absolute/path/to/was_cyber_platform-0.8.0-py3-none-any.whl')
issued = int(time.time())
payload = {
    'schema': 'was.release/1',
    'repository': 'Waseem-gtt/was',
    'sequence': 1,  # زد الرقم لكل بيانات إصدار مختلفة
    'version': '0.8.0',
    'commit': commit,
    'issued_at': issued,
    'expires_at': issued + 7 * 24 * 60 * 60,
    'artifacts': [{
        'name': artifact.name,
        'sha256': hashlib.sha256(artifact.read_bytes()).hexdigest(),
        'size': artifact.stat().st_size,
    }],
}
pathlib.Path('release-payload.json').write_text(
    json.dumps(payload, ensure_ascii=False, indent=2) + '\n', encoding='utf-8')
PY
.venv/bin/python -m cyber_platform.release_admin sign \
  release-payload.json "$HOME/was-signing/publisher.pem" release-signed.json
```

التوقيت Unix بالثواني يعبر عن UTC. الصلاحية أكثر من الصفر وحتى30 يومًا من وقت الإصدار. يُرفض إصدار مؤرخ في المستقبل أو منتهي الصلاحية. أسماء الحزم أسماء ملفات فقط، بلا مسارات أو `..`. يسمح المخطط بحد أقصى16 حزمة، كل منها حتى128MiB؛ فحص الملفات الإداري يحد مجموع الأحجام بـ128MiB. راجع مساحة الإصدار الفعلية قبل إعداد البيانات. لا تتجاوز الأداة الملفات الموجودة عند إنشاء المفتاح أو التوقيع. إنشاء المفتاح وملف الثقة عمليتا كتابة مستقلتان؛ إذا فشلت الثانية فقد يبقى المفتاح الخاص، فافحص المسارين محليًا قبل إعادة المحاولة دون حذف أو استبدال مفتاح مستخدم.

يغطي التوقيع الحقول المحددة في `signed` بترميز JSON معياري لهذه الصيغة: UTF-8، مفاتيح مرتبة، بلا مسافات زائدة. تغيير الإصدار أو التسلسل أو Git أو التوقيت أو قائمة الحزم يغيّر البيانات الموقعة. يُرفض JSON المكرر الحقول والقيم غير المنتهية والحقول غير المعروفة. صيغة التوقيع لا تستخدم لغة JSON Canonicalization Scheme عامة خارج هذا المخطط.

## فحص مستقل دون تثبيت

```bash
install -d -m 700 "$HOME/was-release-state"
.venv/bin/python -m cyber_platform.release_admin verify \
  release-signed.json "$HOME/was-signing/trust.json" \
  --commit FULL_REVIEWED_40_HEX_COMMIT \
  --state "$HOME/was-release-state" \
  --artifacts /absolute/path/to/artifact-directory
```

استبدل `FULL_REVIEWED_40_HEX_COMMIT` بالقيمة الفعلية، والأسماء داخل مجلد الحزم بأسماء الحزم الموقعة. يُفحص كل ملف مسمى بالطول وSHA-256، وتُرفض الروابط الرمزية والملفات غير العادية. النجاح دون `--artifacts` يثبت بيانات الإصدار والتوقيع ومعرّف Git فقط؛ لا يعني فحص بايتات الحزم. المخرجات لا تحتوي كلمات مرور أو مفتاحًا خاصًا.

عند استخدام المتحقق مباشرة في أتمتة إدارية، يمكن إضافة `--trust-digest SHA256` ببصمة سبق للمالك تثبيتها؛ تُفحص المطابقة قبل أي حفظ للحالة. لا تأخذ البصمة المتوقعة من ملف تحديث غير موثوق. مشغّل `release.sh` يمرر بصمة سياسته تلقائيًا.

دون `--record` لا يرفع الفحص تسلسل الحالة؛ قد ينشئ مجلد الحالة وقفلها. `--record` يحفظ الحد الأعلى للتسلسل ذريًا تحت قفل، ولذلك يستخدمه مشغّل التفعيل في مرحلة التثبيت. لا تستخدمه في فحص استطلاعي إذا لم تكن تريد تثبيت حد أعلى جديد. لا تعدّل الحالة أو تحذفها لتجاوز رفض ترقية؛ حذفها يفقد حماية الرجوع إلى إصدار أقدم.

## الإعداد والتفعيل في لينكس

بعد مراجعة معرّف Git وملف الثقة، استخدم خيار التوقيع في مشغّل الإصدار:

```bash
bash scripts/release.sh prepare FULL_REVIEWED_40_HEX_COMMIT /private/was-releases \
  --signed /absolute/path/release-signed.json /absolute/path/trust.json
bash scripts/release.sh activate FULL_REVIEWED_40_HEX_COMMIT /private/was-releases \
  --signed /absolute/path/release-signed.json /absolute/path/trust.json
```

بادئة الإصدارات خاصة بصلاحية0700. يحفظ المشغّل بصمة SHA-256 للتمثيل المعياري لملف الثقة في `PREFIX/.require-signatures`، ولا يقبل الاستبدال الصامت لمفاتيحها أو حد التوقيعات. يمكن نقل ملف الثقة إلى مسار آخر مع بقاء محتواه المعياري نفسه؛ الملف الأصلي لا يُنسخ تلقائيًا إلى البادئة. يُحفظ ملف السياسة بصلاحية0600 وبملكية المستخدم الحالي، ويُرفض الملف الرمزي أو متعدد الروابط أو غير مطابق للصيغة. إعداد إصدار موقّع يثبت إلزام التوقيع لهذه البادئة فور نجاح فحص البيانات، حتى لو فشل إعداد الشيفرة لاحقًا، فلا تصبح الترقية اللاحقة غير موقّعة بمجرد حذف الخيار. راجع فشل الإعداد بدل إزالة ملفات الإلزام أو الحالة. تبديل مفاتيح النشر عملية إدارية مستقلة ومراجعة؛ لا توجد آلية تدوير مفاتيح تلقائية أو قبول أول استخدام.

يبني المشغّل الشيفرة من معرّف Git الموقّع ويجري الفحوص قبل إنشاء علامة الجاهزية؛ لا يثبت wheel ناشر جاهزًا بدل ذلك. لذلك يثبت التوقيع هوية الالتزام المراجع، بينما خيار `--artifacts` في الفحص المستقل يثبت بايتات حزم الناشر. لا تدّع أن wheel المبني محليًا مطابق بايتًا بحزمة الناشر لمجرد تطابق معرّف Git. التوقيع لا يغني عن مراجعة الشيفرة أو قفل الاعتماديات أو الفحوص الوظيفية والأمنية.

توجد حالة التسلسل في `PREFIX/signature-state/release-state.json`. التفعيل يرفض التسلسل الأقل من آخر تسلسل مسجل، ويرفض بيانات مختلفة عند التسلسل نفسه. إعادة فحص البيانات نفسها مقبولة خلال صلاحيتها. الرجوع الصريح إلى إصدار محلي سابق للإصلاح الطارئ يبقى إجراءً إداريًا منفصلًا:

```bash
bash scripts/release.sh rollback /private/was-releases
```

يتحقق الرجوع من سلامة النسخة المحلية المعدة، لكنه استثناء تعافٍ يختاره المالك؛ لا يعيد توقيعها ولا يخفض حد التسلسل المحفوظ للترقيات التالية. لا تتعامل معه كتحديث جديد مصادق عليه. لا تستطيع هذه الحماية منع مالك نظام التشغيل من تبديل ملفات الثقة أو حذف الحالة أو تعديل المشغّل نفسه.

## حدود إدارة الثقة

يدعم المتحقق من مفتاح واحد حتى8 مفاتيح Ed25519 وحدًا أدنى من التوقيعات الموثوقة. إنشاء المفتاح يولّد ملف ثقة بحد أدنى1؛ أمر `sign` يولّد توقيعًا واحدًا. جمع عدة توقيعات مستقلة وإدارة سياسة متعددة الموقّعين يتطلب إعدادًا إداريًا مراجعًا، ولا توجد واجهة جاهزة لتنسيقه. يُرفض أي توقيع غير معروف أو تالف أو مكرر حتى لو تحققت توقيعات أخرى كافية. ملفات الثقة لا تحدّث نفسها من بيانات الإصدار.

التحقق ليس مسحًا للثغرات ولا يضمن سلامة الناشر أو النظام المضيف. لا توجد خدمة تثبيت عامة، أو صلاحية تنفيذ من واجهة HTTP، أو تفويض للنموذج المحلي بإصدار مفاتيح أو توقيع ترقيات. تبقى بيانات المالك والأدلة والنماذج والمفاتيح خارج Git وحزم التسليم.
