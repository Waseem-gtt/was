# تشغيل Linux وVirtualBox

## جهاز Linux

للتشغيل من قائمة تطبيقات لينكس أو تجهيز ترقية مفحوصة مع رجوع للإصدار السابق، راجع [دليل الصيانة والترقية](Maintenance.md). مشغّل سطح المكتب يفتح الواجهة الخاصة في المتصفح المحلي؛ ليس صورة نظام تشغيل أوOVA.

Debian 13 أو Ubuntu مدعوم مع Python 3.11+، ومعالجان وذاكرة 3 GB نقطة بداية للنواة فقط. النموذج المحلي والبيئات الكبيرة تحتاج قياسًا مستقلًا. سكربت التثبيت ينشئ venv ويثبت اعتماد التشفير ثم يشغّل الاختبارات؛ لا يثبّت حزم النظام أو يغيّر إعداداته بصمت.

للخدمة التلقائية، بعد وضع المستودع في `~/was` وإجراء التثبيت:

```bash
mkdir -p ~/.config/systemd/user
cp deploy/was-platform.service ~/.config/systemd/user/
systemctl --user daemon-reload
systemctl --user enable --now was-platform
systemctl --user status was-platform
```

عدّل WorkingDirectory وExecStart إذا اختلف مسار المستودع. الخدمة user service دون root؛ لم يُختبر systemd في بيئة البناء الحالية. لتشغيلها قبل تسجيل الدخول يلزم قرار مدير الجهاز بشأن user lingering. لا تفعّله ضمنيًا.

تحقق من `/healthz` ثم أنشئ مشروعًا وحلّل دليلًا؛ نجاح المنفذ وحده لا يثبت جاهزية التطبيق. سجلات HTTP لا تسجّل أسماء الملفات أو الأسئلة أو كلمات المرور. جلسات الدخول في الذاكرة وتنتهي بعد ثماني ساعات أو إيقاف الخدمة.

## ضيف VirtualBox

**لا توجد صورة OVA مبنية أو مختبرة لهذا التنفيذ.** أرقام الإصدارات وبصمات الأجهزة القديمة في الوثيقة تاريخ لم تُرفق ملفاته، وليست نتائج هذا المستودع.

للتجهيز اليدوي على جهاز المالك:

1. أنشئ ضيف Debian/Ubuntu من ISO رسمي وتحقق من بصمته وفق موقع التوزيعة. ابدأ بقرص ديناميكي 20 GB، ومعالجين و3 GB RAM. توسيع الحد إلى35 GB يحتاج توسيع القرص ونظام الملفات فعليًا.
2. ثبّت حزم Python وGit وBubblewrap من مستودعات التوزيعة الموقعة.
3. انقل/استنسخ المستودع الخاص باستخدام مصادقة GitHub المعتادة، ثم نفّذ تعليمات README داخل الضيف.
4. لا تفتح منفذ التطبيق على واجهة عامة. للوصول من المضيف استخدم SSH محليًا: تحويل NAT لمنفذ SSH مقيد بعنوان loopback للمضيف، ثم نفق إلى منفذ8080 في الضيف. يفتح المالك متصفح المضيف على المنفذ المحلي للنفق. احم حساب SSH بمفتاح ولا تحفظه في القالب.
5. اختبر إنشاء المشروع والرفع والتحليل والنسخ والاستعادة داخل الضيف. اختبر الورشة بعينة تمنع شبكة المضيف وقراءة ملف خارج `/work`، وسجل النتيجة.
6. قبل تصدير قالب، أوقف الخدمات وأزل بيانات الاختبار وحساباته ومفاتيح SSH الخاصة ورموز GitHub وملف setup-token من نسخة مخصصة للقالب. احتفظ بنسخة المالك الأصلية منفصلة.
7. صدّر OVA من VirtualBox وسجل الحجم وSHA256، ثم استورد النسخة المصدرة إلى جهاز جديد واختبر إقلاعها وتشغيلها. لا تعتبر نجاح التصدير اختبارًا للاستيراد أو التشغيل.

هذه خطوات تجهيز، وليست تقرير نجاح. لا يُفعّل الوصول من الجوال أو ربط أجهزة مادية في النسخة الحالية. لا تحتاج النواة إلى شراء أو اشتراك.
