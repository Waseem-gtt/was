# مراجعة الأمان والفحوص — الإصدار 0.4

## ما تحقق

- نجح92 اختبارًا على كل من CPython3.11.17 و3.12.14 و3.13.5 في البيئة الحالية.
- نجحت17 مجموعة سيناريو في Chromium،وكذلك باستخدام Playwright1.58.0 المطابق لقيد CI مع متصفح المضيف، تتضمن إنشاء المالك برمز خاص، والاستكمال المتحقق، ومقارنة النتائج، والنسخ المشفر، وواجهات320 و390 بكسل.
- فُحص كود التطبيق باستخدام Bandit1.9.4. النتيجة: لا تنبيهات غير معالجة، ولا أخطاء تحليل ملفات. توجد أربعة استثناءات موضعية مبررة أدناه؛ لا تعطيل شامل لقواعد الفحص.
- فُحصت الاعتمادات التشغيلية المقفلة باستخدام pip-audit2.10.1 وخدمة PyPI: cffi2.1.1 وcryptography50.0.2 وpycparser3.11. لم يُرجع الفحص الحالي ثغرات معروفة لها. لا يعني ذلك غياب ثغرات غير معروفة، ولا يشمل كل حزم نظام التشغيل أو أدوات البناء.
- صار تثبيت الاعتمادات باستخدام requirements.lock وبصمات SHA-256، وثبتت Actions v6 على commits محددة،وبيئة التشغيل على Ubuntu24.04. لم يُعطل TLS أو التحقق من البصمات.

## إصلاحات فعلية

1. **تهيئة المالك:** كان أي عميل يصل إلى loopback قبل إنشاء المالك قادرًا على محاولة حجز الحساب. أصبحت التهيئة تتطلب رمزًا عشوائيًا خاصًا محفوظًا في ملف0600 تحت مجلد البيانات0700، لا تعرضه واجهة عامة ويحذف بعد نجاح التهيئة. الحسابات السابقة تبقى دون تعديل.
2. **قراءة الطلبات:** أصبحت المصادقة وCSRF قبل قراءة جسم كبير للمسارات الخاصة. حد جسم الدخول والتهيئة4096 بايت؛ لا يمكن لعميل غير مسجل طلب قراءة24MiB قبل رفضه.
3. **التباس البروتوكول:** رُفضت ترويسات Host وContent-Length المكررة وTransfer-Encoding، وJSON ذو مفاتيح مكررة أو أعداد NaN/Infinity. لا تستخدم المنصة CORS لتوسيع الوصول.
4. **حد الاتصالات:**16 عامل طلب متزامنًا ومهلة قراءة تبدأ قبل تحليل الترويسات، بدل إنشاء عدد غير محدود من عمال HTTP.
5. **ملفات الأدلة:** رفض مسار قاعدة بيانات أو مجلد أدلة رمزي، ورفض أسماء التحكم، وقراءة الدليل بفتح O_NOFOLLOW وفحص نوعه وحجمه وبصمته على الملف المفتوح نفسه. مجلد البيانات يجب أن يكون خاصًا0700.
6. **موارد المحللات:** تعمل الأدوات الموثوقة على ملفات المالك في مفسر Python جديد، بحد384MiB و3ثوانٍ CPU و10ثوانٍ انتظار نتيجة، مع إيقاف العامل المتجاوز ونتيجة فشل محفوظة. لا رجوع للتنفيذ داخل الخدمة عند الفشل. اختبر مدخل نصي مكلف ثم نجاح التحليل التالي.
7. **الاستكمال:** لا تعاد نتيجة منجزة دون التحقق من خطة الأصل وإصدار وبصمة المحرك وملفات المدخلات والمخرجات ومعايير قبولها. تنشأ مهمة جديدة، ويظل الفشل الأصلي محفوظًا.
8. **المقارنة:** لا تستخدم إلا نتائج تحليل من المشروع نفسه والأداة نفسها. لها حدود عدد وعمق وزيارات، وتظهر المقارنة الناقصة بوضوح بدل إعلان التساوي.
9. **تشغيل الورشة:** استُخدم غلاف prlimit ثابت قبل Bubblewrap بدل preexec_fn داخل الخادم متعدد الخيوط. إذا غابت إحدى الأداتين يرفض التشغيل؛ لا إلغاء للعزل أو حدود الموارد.
10. **اشتقاق كلمة المرور:** رفع كلفة Scrypt إلى N=131072 مع حدود ذاكرة وتنفيذ متسلسل،وترقية الاعتمادات القديمة بعد نجاح الدخول فقط مع ملح جديد. صيغة النسخ الاحتياطية تبقى متوافقة.
11. **تدقيق الدخول:** نجاح الدخول وفشله يسجلان دون كلمة مرور أو رمز جلسة أو رمز تهيئة.

## ملاحظة الفحوص الحمراء

أعيد إنتاج فشل اختبار العزل عند **محاكاة غياب Bubblewrap**: التطبيق كان يرفض التنفيذ503، لكن الاختبار يفشل لأن الرسالة لا تحتوي كلمة«عزل» التي يتحقق منها. صُححت الرسالة وأضيف اختبار مستقل يثبت عدم تشغيل أي عملية عند غياب الأداة. اختبارات الدعم لا تحول رفض العزل إلى ادعاء نجاح تشغيله.

لم تُقرأ سجلات GitHub Actions البعيدة من هذه البيئة: أعاد gh عبارة Forbidden، ونطاق api.github.com غير مدرج في إعداد الاتصال المتاح. أضيف النطاق إلى مسودة إعداد البيئة مع الحفاظ على بقية إعدادات الشبكة. حفظ المسودة لا يطبقها أو ينشرها؛ يلزم مراجعتها وحفظها ونشر البيئة من إعداداتها. لذلك لا ينسب فشل GitHub حصرًا إلى العيب المحلي، ولا يعلن نجاح أحدث تشغيل بعيد قبل رؤية نتيجته.

الفحوص المحفوظة في CI تشمل الاختبارات عبر ثلاث نسخ Python، وبناء wheel، وفحص المصدر، وتدقيق الاعتمادات المقفلة، وسيناريوهات المتصفح. لا تستخدم continue-on-error أو تجاهل CVE أو تقليل الاختبارات لإخفاء فشل.

## استثناءات Bandit المراجعة

- B404 في sandbox.py: استيراد subprocess مطلوب لمشغل Bubblewrap الثابت.
- B603 في الموضع نفسه: قائمة أوامر ثابتة وبدون shell؛ كود الورشة ملف مركب داخل العزل الإلزامي، ولا يدخل في نص أمر shell.
- B108: المسار /tmp هو tmpfs جديد داخل namespace، وليس ملفًا مؤقتًا غير آمن على المضيف. ملفات المضيف المؤقتة تنشأ بواسطة TemporaryDirectory.
- B105 في server.py: سلسلة token الفارغة علامة فشل لتحليل cookie، وليست كلمة مرور أو جلسة صالحة.

## حدود الأمان

عامل المحللات حد موارد للكود الموثوق، وليس namespace ملفات أو شبكة أو بديلًا عن VM. ورشة Python غير الموثوقة ما زالت تتطلب Bubblewrap وتفشل مغلقة عند غيابه. لا تدعى حماية مضيف مخترق أو تشفير قاعدة البيانات الأصلية أو خدمة جاهزة للنشر العام. تظل الملفات خاصة بالمضيف والمستودع الذي أكد المالك خصوصيته. لا نتيجة فحص محددة تمنح ضمان أمان100% أو تعني اكتمال المشروع كله.
